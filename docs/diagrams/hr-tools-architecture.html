人事ツール構成図

デモアプリの「人事ツール」が、受講者の質問からツール実行までどう動くかを示します。人事ツールは AgentCore Gateway ではなく、エージェントの中のコードとして動きます。権限の判定はモデルの外で、ログインの証明（トークン）を使って行います。

要求 応答（ストリーミング） 本人の情報（会話の外から渡す） 読む確認なしで実行 書く下書き → 本人の承認 → 提出 チェックモデルの外のコードで判定

1 回の流れ（例：「B さんの給与明細を見せて」）

  1. 受講者が設定で人事ツールをオンにして質問します。ブラウザは Cognito のトークンを付けて送ります。
  2. Chat Lambda は管理設定で人事ツールが使えるか確かめ、hrToolsEnabled と今日の日付を付けて、利用者のトークンのまま AgentCore Runtime を呼びます。
  3. Runtime がトークンを検証します。エージェントはその sub から社員番号を決めます。
  4. モデルが get_payslip(employee="Bさん") を呼ぶと決めます。
  5. ツールは引数を社員番号と照合し、本人ではないので ACCESS_DENIED を返します。金額は作らないので、モデルに渡りません。
  6. 回答と一緒に実行記録（toolCalls）が返り、画面に「人事ツールを 1 回実行しました（アプリが 1 件を止めました）」と表示されます。同じ内容が CloudWatch Logs にも残ります。

要点

判定はモデルの外で行う

本人照合と承認ガードはツールのコードにあります。プロンプトでモデルをだましても、他人の明細を作る仕組みがありません。

人事データは DB なし

金額と休暇の初期値はコードの固定値です。申請の状態は会話履歴から計算し直すので、「クリア」で初期状態に戻ります。

受講者の操作は on / off だけ

管理者が「利用可能なツール」で人事ツールを許可し、受講者は設定でオンにするだけで一通り試せます。

本番なら Gateway の後ろへ

実際の人事システムにつなぐなら、人事 API を AgentCore Gateway のターゲットにします。本人の判定は API 側で行います。
