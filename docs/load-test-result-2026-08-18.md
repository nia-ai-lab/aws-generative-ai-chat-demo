# 30同時実行負荷試験結果（2026-08-18）

## 1. 結論

最大30人の同時チャット利用に必要なAPI基盤容量は合格と判定する。完全同時開始した30セッションで2ターン、合計60チャットリクエストと事前ウォームアップ1件を実行し、HTTP、SSE、Lambda、API Gatewayのエラーおよびスロットリングは0件だった。

AgentCore Memoryにはセッションごとの会話履歴が保存・復元され、他セッションの値が回答へ混入した事例は0件だった。Nova Microによる計算回答は29/30一致し、残り1件は履歴を読み込んだうえで数値を個人情報と誤判定した安全拒否だった。この1件は可用性、Memory、セッション分離の障害ではなく、モデル回答品質として記録する。

## 5. Memoryとモデル回答の評価

- 全30セッションで、2ターン目のモデル入力トークン数が1ターン目より増え、過去メッセージが入力へ含まれた。
- 抽出確認したAgentCore Memoryセッションには、`利用者 → AI → 利用者 → AI`の4メッセージが保存されていた。
- 30セッション中29件は、各セッション固有の`X + 1`を正しく回答した。
- 残り1件も履歴を読み込んでいたが、Nova Microが数値回答を個人情報として拒否した。
- 他セッションの計算結果を回答した事例は0件だった。

これらから、短期Memoryとセッション分離は正常、完全一致率96.7%はNova Microの安全拒否による回答品質上の結果と判断する。

## 6. 試験中に発見・修正した容量制約

初回試験ではLambda Authorizerの予約済み同時実行数が20で、2ターン目の30同時要求のうち9件がスロットリングされ、API Gatewayで5xxとなった。

Authorizerの予約済み同時実行数を40へ変更後、同条件の再試験でAuthorizer ThrottlesとAPI Gateway 5xxはいずれも0件になった。Reserved Concurrencyの変更自体に待機料金は発生しない。
