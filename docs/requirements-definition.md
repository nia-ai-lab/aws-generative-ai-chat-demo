# Generative AI Chat 要件定義書

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| システム名 | Generative AI Chat |
| 用途 | Generative AI Essentials on AWS の講義・デモ・受講者演習 |
| 対象環境 | `DEPLOY_ACCOUNT_ID` で指定する AWS アカウント、`ap-northeast-1` |
| 対象利用者 | 一般受講者、講師・管理者 |
| 文書ステータス | 実装反映版 |
| 作成日 | 2026-08-16 |

## 2. 背景と目的

本アプリケーションは、受講者がブラウザから生成 AI の基本的なチャット操作を体験し、モデル選択、システムプロンプト、会話メモリ、安全対策、認証・認可、監査ログといった生成 AI アプリケーションの構成要素を理解するための一時的なトレーニング環境である。

教材では、モデル選択、システムプロンプトとユーザープロンプト、プロンプト攻撃、多層防御、AgentCore Runtime・Memory・Observability、責任ある AI、ガバナンスを扱っている。本アプリケーションはこれらを一つの操作可能なデモとして結び付ける。

### 2.1 学習上の位置付け

- モジュール 2: モデルごとの品質、速度、コストの違いをモデル切り替えで体験する。
- モジュール 4: システムプロンプトとユーザープロンプトの役割の違いを体験する。
- モジュール 5: プロンプトだけに依存しない安全対策を確認する。
- モジュール 6: AgentCore Runtime、短期メモリ、セッション分離、オブザーバビリティを確認する。
- モジュール 7: 認証、認可、ログ、説明責任を確認する。

## 3. スコープ

### 3.1 対象範囲

- ブラウザで動作する React SPA
- Cognito によるログイン
- 一般受講者向け AI チャット
- 受講者ごとのブラウザセッション分離
- ブラウザセッション単位で分離された利用者システムプロンプト
- 管理者によるモデルとアプリ既定プロンプトの管理
- AgentCore Runtime 上の LangGraph Agent
- AgentCore Memory による会話セッション内の短期記憶
- CloudWatch Logs による全チャットの監査記録
- Amplify Gen 2 と CDK による一括デプロイ
- トレーニング終了後の環境削除

### 3.2 対象外

- 受講者ごとの恒久アカウント発行
- 受講者を恒久的に識別して引き継ぐ長期記憶・利用者プロファイル
- チャット履歴一覧、過去の会話の再開、検索、エクスポート
- ファイル添付、画像生成、音声入力、RAG、外部ツール実行
- 課金、商用 SLA、マルチテナント契約管理
- 本番業務データや機密情報の入力
- 管理画面からの任意 Bedrock モデル追加に伴う IAM ポリシー変更

## 4. 用語

| 用語 | 定義 |
|---|---|
| アクセストークン | Cognito User Pool が発行する OAuth 2.0 JWT。AWS の Access Key ID/Secret Access Key ではない。 |
| ブラウザセッション | 同一タブでログインしてからタブを閉じるまでの操作単位。`sessionStorage` を利用する。 |
| 会話セッション | クリア操作まで継続する一つの会話。AgentCore Runtime/Memory のセッションに対応する。 |
| アプリ既定プロンプト | 管理者が設定し、全受講者の全会話に適用するシステムプロンプト。 |
| 利用者プロンプト | 受講者が設定画面で指定する人格・口調などの追加システム指示。 |
| 短期メモリ | 同じ会話セッション内の履歴を保持する AgentCore Memory。別セッションには引き継がない。 |

## 5. 利用者と権限

| ロール | 認証方式 | 権限 |
|---|---|---|
| 一般受講者 | 共有のユーザー名・パスワード | チャット、モデル選択、利用者プロンプト設定、会話クリア |
| 管理者 | 管理者専用ユーザー名・パスワード | 一般受講者の全機能、利用可能モデル・既定モデル・アプリ既定プロンプトの変更 |

- Cognito の自己サインアップは無効とする。
- 一般受講者用ユーザーと管理者用ユーザーは事前作成する。
- Cognito グループ `Students` と `Admins` でロールを表現する。
- 画面上の表示制御に加え、API 側でも毎回ロールを検証する。

## 6. 機能要件

### 6.1 認証・セッション

| ID | 要件 |
|---|---|
| AUTH-01 | 利用者はユーザー名とパスワードでログインできること。 |
| AUTH-02 | 未認証利用者はチャット画面および管理機能へアクセスできないこと。 |
| AUTH-03 | API Gateway の Lambda Authorizer は Cognito Access Token の署名、発行元、App Client ID、有効期限、`token_use=access` を検証すること。 |
| AUTH-04 | AgentCore Runtime も同じ Cognito JWT を Custom JWT Authorizer で検証すること。 |
| AUTH-05 | Lambda は受信した JWT を AgentCore Runtime に転送し、ログに出力しないこと。 |
| AUTH-06 | Cognito の `cognito:groups` クレームにより一般受講者と管理者を識別すること。 |
| AUTH-07 | ログアウト時にブラウザ上のトークン、会話表示、利用者設定を破棄すること。 |

### 6.2 チャット

| ID | 要件 |
|---|---|
| CHAT-01 | 利用者はテキスト入力欄から AI にメッセージを送信できること。 |
| CHAT-02 | 日本語の入力・表示・応答に対応すること。 |
| CHAT-03 | Enter で送信し、Shift+Enter で入力欄内を改行できること。 |
| CHAT-04 | IME の変換確定中に Enter を押しても送信されないこと。 |
| CHAT-05 | 応答待ちの間は `AI Thinking...` を表示すること。 |
| CHAT-06 | AI 応答は可能な限り逐次表示すること。ストリーム開始後は `AI Thinking...` を応答表示に置き換えること。 |
| CHAT-07 | 同一会話セッション内では、それまでの会話内容を踏まえて応答すること。 |
| CHAT-08 | 送信中の多重送信を防止すること。 |
| CHAT-09 | 入力値の前後空白のみのメッセージは送信できないこと。 |
| CHAT-10 | メッセージ長、会話長、出力トークン数に上限を設け、過大な利用を防止すること。 |
| CHAT-11 | エラー時は技術詳細や内部プロンプトを露出せず、再試行可能なメッセージを表示すること。 |

### 6.3 会話のクリアと分離

| ID | 要件 |
|---|---|
| SESSION-01 | ブラウザセッション開始時に推測困難な一意の ID を生成すること。 |
| SESSION-02 | 会話開始時に UUID v4 の会話セッション ID を生成すること。 |
| SESSION-03 | 同じ Cognito ユーザーで複数人が同時ログインしても、ブラウザセッションおよび会話内容が混ざらないこと。 |
| SESSION-04 | クリアボタンで画面上の履歴を削除し、新しい会話セッション ID を生成すること。利用者プロンプトは現在のブラウザセッション中は維持すること。 |
| SESSION-05 | クリア後の AI は、クリア前の会話を参照しないこと。 |
| SESSION-06 | クリアは監査ログの削除を意味しないこと。監査ログは所定の保持期間まで残ること。 |
| SESSION-07 | Chat Lambda は認証主体、ブラウザセッション、会話セッションから AgentCore の長さ要件を満たす `runtimeSessionId` を導出すること。 |
| SESSION-08 | バックエンドは Cognito の共有ユーザー ID だけをキーとして利用者設定を保存または取得してはならず、`browserSessionId` と必要に応じて `conversationSessionId` を分離キーに含めること。 |
| SESSION-09 | `runtimeSessionId` と認証主体の対応をバックエンドで検証し、クライアントが別ブラウザセッションの ID を指定して参照できないこと。 |

### 6.4 プロンプト

| ID | 要件 |
|---|---|
| PROMPT-01 | 全会話に、固定の最低限安全ポリシーを最優先で適用すること。 |
| PROMPT-02 | 管理者が変更できるアプリ既定プロンプトを全会話に適用すること。 |
| PROMPT-03 | 受講者は設定ダイアログで人格、口調、応答形式などの利用者プロンプトを設定できること。 |
| PROMPT-04 | 利用者プロンプトはブラウザセッション単位で分離すること。保存先は限定しないが、共有 Cognito ユーザーを使う別受講者へ引き継がれないこと。 |
| PROMPT-04A | 利用者プロンプトを AgentCore Runtime または AgentCore Memory に保持する場合、アプリが検証した `browserSessionId` を含む分離キーを使用すること。 |
| PROMPT-05 | 利用者プロンプトは固定安全ポリシーおよび管理者プロンプトを上書きできないものとして区切って渡すこと。 |
| PROMPT-06 | 管理者プロンプトと利用者プロンプトは、通常の会話メッセージとは別の system 指示として扱うこと。 |
| PROMPT-07 | Bedrock Guardrails により、入力と出力の双方に最低限のコンテンツ保護を適用すること。 |

### 6.5 モデル選択

| ID | 要件 |
|---|---|
| MODEL-01 | チャット画面で、管理者が有効化したモデルから一つを選択できること。 |
| MODEL-02 | 初期候補は Claude Sonnet 5、Nova 2 Lite、Nova Pro とすること。 |
| MODEL-03 | 管理者は有効モデルの組み合わせと既定モデルを変更できること。 |
| MODEL-04 | 管理者が無効化したモデルは新規送信に利用できないこと。 |
| MODEL-05 | API および Agent は、クライアントが送信したモデル ID が管理者設定の許可リストに含まれることを検証すること。 |
| MODEL-06 | 新しいモデルファミリーの追加や IAM 権限変更は、CDK の更新と再デプロイを必要とすること。 |

### 6.6 管理機能

| ID | 要件 |
|---|---|
| ADMIN-01 | 管理者だけに管理設定ダイアログを表示すること。 |
| ADMIN-02 | 管理者はアプリ既定プロンプトを表示・更新できること。 |
| ADMIN-03 | 管理者は有効モデルと既定モデルを表示・更新できること。 |
| ADMIN-04 | 管理設定は DynamoDB に保存すること。 |
| ADMIN-05 | 同時更新による上書きを防ぐため、設定バージョンによる楽観的ロックを行うこと。 |
| ADMIN-06 | 設定更新者、更新日時、設定バージョンを記録すること。 |
| ADMIN-07 | 管理者 API は画面表示の有無に関係なく、サーバー側で `Admins` グループを必須とすること。 |

### 6.7 監査・ログ

| ID | 要件 |
|---|---|
| LOG-01 | すべてのユーザーメッセージと AI 応答を CloudWatch Logs に構造化 JSON で記録すること。 |
| LOG-02 | リクエスト ID、会話セッション ID、選択モデル、開始・終了時刻、レイテンシー、トークン使用量、結果種別を記録すること。 |
| LOG-03 | AgentCore の推論、メモリ操作、応答生成をトレース可能にすること。 |
| LOG-04 | パスワード、Cognito JWT、Cookie、認証ヘッダー、AWS 認証情報は記録しないこと。 |
| LOG-05 | 管理設定の変更を監査ログに記録すること。 |
| LOG-06 | CloudWatch Logs は KMS で暗号化し、閲覧権限を管理者に限定すること。 |
| LOG-07 | トレーニング環境のログ保持期間は 7 日とし、環境削除時に削除できること。 |

### 6.8 UI/UX

| ID | 要件 |
|---|---|
| UI-01 | アプリのタイトルは `Generative AI Chat` とすること。 |
| UI-02 | 画面は必要最低限の文字と操作要素で構成し、直感的に操作できること。 |
| UI-03 | ログイン画面、チャット画面、利用者設定ダイアログ、管理者設定ダイアログを提供すること。 |
| UI-04 | PC ブラウザを主対象とし、iPhone Safari でも操作可能なレスポンシブデザインとすること。 |
| UI-05 | キーボード操作、フォーカス表示、適切な ARIA 属性、十分なコントラストを備えること。 |
| UI-06 | ヘッダーのアイコンボタンは、マウスホバーまたはキーボードフォーカス時に操作名を表示すること。 |
| UI-07 | 管理者以外には管理操作を表示しないこと。 |
| UI-08 | 送信、クリア、設定、モデル選択、ログアウトの主要操作を一画面から実行できること。 |

### 6.9 デプロイと削除

| ID | 要件 |
|---|---|
| DEPLOY-01 | Amplify Gen 2 を使用して Git リポジトリからデプロイできること。 |
| DEPLOY-02 | Amplify Gen 2 の TypeScript バックエンドに CDK カスタムリソースを組み込み、フロントとバックエンドを一度にデプロイできること。 |
| DEPLOY-03 | Agent のみ Python 3.12、その他のアプリケーションコードと CDK は TypeScript とすること。 |
| DEPLOY-04 | Agent の依存関係を ARM64 対応 ZIP にパッケージし、AgentCore Runtime に Direct Code Deployment すること。 |
| DEPLOY-05 | デプロイ先アカウントをリポジトリ外の `DEPLOY_ACCOUNT_ID` で指定し、リージョンを明示的に固定すること。指定と実セッションが一致しない場合はデプロイを失敗させること。 |
| DEPLOY-06 | `cdk synth` 相当の合成、静的検査、テスト、デプロイ後スモークテストを自動化すること。 |
| DEPLOY-07 | トレーニング終了後、一つの手順でアプリ固有リソースを削除できること。 |
| DEPLOY-08 | GitHub リポジトリ作成前でもローカル開発可能とし、実装開始時に新規リポジトリ作成を案内すること。 |

## 7. 非機能要件

### 7.1 性能・容量

| ID | 暫定目標 |
|---|---|
| NFR-PERF-01 | 最大同時受講者 30 名に対応すること。 |
| NFR-PERF-02 | 通常の最初の応答表示を P95 15 秒以内とする。モデルの混雑やコールドスタートは除外して監視する。 |
| NFR-PERF-03 | 入力上限は暫定 8,000 文字、AI 出力上限は暫定 1,024 トークンとする。 |
| NFR-PERF-04 | API、Lambda、AgentCore の各レイヤーにスロットリングと同時実行上限を設定する。 |

### 7.2 可用性・信頼性

- 一時的なトレーニング環境のため商用 SLA は設定しない。
- モデルのスロットリング、タイムアウト、一時障害を分類し、指数バックオフの対象を限定する。
- 同じメッセージの誤再送を避けるため、リクエスト ID を付与する。
- 設定 API は条件付き更新により整合性を保つ。

### 7.3 セキュリティ

- 通信はすべて TLS を使用する。
- Cognito アクセストークンを API の認可に使用する。
- Lambda、AgentCore Runtime、デプロイ処理には用途別の IAM ロールを使用する。
- IAM ポリシーは対象 API、モデル、テーブル、ロググループ、S3 アセットに限定する。
- CORS は Amplify の実際のオリジンだけを許可する。
- CSP、`X-Content-Type-Options`、`Referrer-Policy` などのセキュリティヘッダーを設定する。
- システムプロンプトは安全機構の一部であり、単独のセキュリティ境界とはみなさない。
- 入力値をスキーマ検証し、プロンプト、モデル ID、セッション ID、設定サイズを制限する。

### 7.4 プライバシー

- 本アプリには個人情報、認証情報、顧客データを入力しないよう受講者へ案内する。
- 会話は監査要件により記録されるため、チャットのクリア後もログ保持期間中は CloudWatch Logs に残る。
- AgentCore Memory は短期メモリだけを使用し、長期記憶戦略を設定しない。
- AgentCore Memory のイベント有効期間はサービス許容最小値の 3 日とし、トレーニング終了時は環境を削除する。

### 7.5 保守性

- TypeScript は strict mode、Python は型注釈を必須とする。
- フロント、API 契約、DynamoDB 設定スキーマを共通の型定義から生成または検証する。
- モデルの表示名と実 ID を分離し、モデル ID を UI に直接ハードコードしない。
- 依存関係のロックファイルをコミットする。

## 8. 受入条件

1. 2 台以上の端末で共有受講者アカウントに同時ログインし、互いの会話が参照されない。
2. 同じ会話で「私の名前は田中です」の後に「私の名前は？」と質問し、文脈を保持して回答する。
3. クリア後に同じ質問を行い、クリア前の名前を参照しない。
4. 日本語 IME の変換確定 Enter では送信されず、確定後の Enter でのみ送信される。
5. Shift+Enter で改行し、Enter で送信できる。
6. 送信後、応答開始まで `AI Thinking...` が表示される。
7. 3 モデルを切り替え、選択したモデルで応答できる。
8. 一般受講者が管理 API を直接呼び出しても `403` になる。
9. 管理者の設定変更が DynamoDB に保存され、再ログイン後も反映される。
10. 同じ共有 Cognito ユーザーでログインした別ブラウザセッションに、利用者プロンプトが引き継がれない。
11. API Gateway と AgentCore Runtime の両方で無効・期限切れ JWT が拒否される。
12. CloudWatch Logs で各会話の入力、出力、モデル、セッション、結果を追跡でき、JWT は含まれない。
13. PC と iPhone の主要ブラウザで主要操作が完了できる。
14. Amplify の一回のパイプライン実行でバックエンド、Agent、フロントがデプロイされる。

## 9. 前提・暫定決定

- 受講者用共有ユーザーは 1 個、管理者ユーザーは最低 1 個とする。
- 既定選択モデルは暫定で Claude Sonnet 5 とする。
- 3 モデルはすべて初期状態で有効とする。
- UI は日本語を基本とし、製品名、モデル名、`AI Thinking...` は英語表記を許容する。
- カスタムドメインは初期スコープ外とし、Amplify の標準ドメインを利用する。
- 最大同時利用者数は 30 名とする。
- CloudWatch Logs の保持期間は 7 日とする。
- Claude Sonnet 5、Nova 2 Lite、Nova Pro はクロスリージョン推論プロファイルを使用する。
- リソース削除を前提とするため、DynamoDB とログの削除保護は有効化しない。
